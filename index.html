01 / THE IDEA

What problem does it solve?

Hierarchical clustering builds a hierarchy of nested groups. In agglomerative clustering, each observation begins as its own cluster; the algorithm repeatedly merges the closest clusters until one group remains or a stopping rule is reached. The result is often shown as a dendrogram, which lets the reader inspect group structure at multiple cut heights.

A single K-Means solution requires choosing K before fitting. Hierarchical clustering instead records a sequence of merges, allowing the analyst to explore several possible group counts after seeing the tree. The merge pattern depends on the distance metric and linkage rule.

At each merge, select the pair of clusters with the smallest linkage distance under the chosen rule.

02 / METHOD

How it works, step by step

  1. 01
    Choose and prepare features; scale them when appropriate.
  2. 02
    Calculate pairwise distances between observations.
  3. 03
    Start with each row as a separate cluster.
  4. 04
    Merge the closest pair according to the chosen linkage definition.
  5. 05
    Record merge heights in a dendrogram and choose a cut that fits the analysis goal.

03 / VOCABULARY

Concepts worth knowing

Dendrogram

A tree-like plot where leaves are observations and branch heights indicate merge dissimilarity.

Linkage

A rule for measuring distance between clusters, such as single, complete, average, or Ward linkage.

Single linkage

Uses the closest pair across two clusters; can create chaining.

Complete linkage

Uses the farthest cross-cluster pair; often favours tighter groups.

Ward linkage

Merges groups to minimise the increase in within-cluster variance, typically with Euclidean geometry.

Cut height

A horizontal level chosen on the dendrogram; branches below the cut form the resulting clusters.

04 / IN PRACTICE

A realistic use case

A researcher might group regions based on several standardised service indicators. The dendrogram helps show which regions are most similar and whether a small number of larger families can summarise the data. The chosen cut still needs interpretation and validation.

Questions to ask before trusting the result

  • Does the data represent the population or workflow where the model will be used?
  • Are important features missing, noisy, or measured after the outcome?
  • Would a wrong prediction have unequal costs for different groups?
  • Can the result be checked on data not used to build or tune the method?

07 / INTERPRETATION

How to interpret the output

A large vertical jump between merge heights can suggest a possible cut, but it is not proof of a uniquely correct cluster count. Compare resulting cluster profiles and assess stability. A dendrogram communicates nested similarity, not causal relationships.

Do not confuse a pattern with proof

A plot is evidence about the rows and variables it displays. It does not by itself establish causation, guarantee performance on future data, or show that a model will remain reliable after the data distribution changes. Document assumptions and evaluate the method in the context where it will be used.

08 / TRADE-OFFS

Strengths and limitations

Where it helps

  • Shows nested relationships at multiple resolutions
  • Does not require a final cluster count at the start
  • Dendrograms can be informative for small datasets
  • Multiple linkage rules provide useful perspectives

Where to be careful

  • Pairwise distance storage can be expensive
  • Results depend on scaling, distance, and linkage
  • Early greedy merges generally cannot be undone
  • Dendrograms become hard to read with many observations

When should you use it?

Use hierarchical clustering for smaller datasets where the relationships between groups matter. Report the distance metric, linkage rule, and cut decision rather than presenting the tree as self-explanatory.

09 / FIELD NOTES

A practical review checklist

  • State the prediction or discovery question in plain language.
  • Document where the data came from and what each row represents.
  • Separate training, model selection, and final evaluation when fitting a model.
  • Use metrics that match the actual task and the cost of errors.
  • Compare with a simple baseline before claiming the method is useful.
  • Explain uncertainty, assumptions, and what the result cannot establish.

10 / TAKEAWAY

What to remember

Use hierarchical clustering for smaller datasets where the relationships between groups matter. Report the distance metric, linkage rule, and cut decision rather than presenting the tree as self-explanatory.

The best workflow is not simply to run an algorithm and show a graph. It is to define the question, prepare the data, explain the method, examine evidence, test limitations, and communicate what can reasonably be concluded.

11 / WORKED EXAMPLE

Worked example: choosing a dendrogram cut

A dendrogram records merges from small groups to larger ones. A horizontal cut through a relatively large vertical gap can be a candidate cluster solution because it avoids merging groups that are noticeably dissimilar. This is a diagnostic, not a proof that the resulting number of clusters is uniquely correct.

  • State the linkage method and distance metric.
  • Describe each resulting cluster using its original feature values.
  • Compare alternative cut heights before committing to a conclusion.

12 / REPRODUCIBLE WORKFLOW

Implementation blueprint

This optional Python example shows the usual workflow for the included CSV. It is source code for running locally, not code that runs inside this static article. Install the listed libraries first, keep the dataset file beside the script, and use the printed output as a starting point for interpretation—not as a substitute for checking assumptions.

import pandas as pd
from sklearn.preprocessing import StandardScaler
from scipy.cluster.hierarchy import linkage, fcluster

df = pd.read_csv("region_profiles_teaching_data.csv")
X = df[["service_index", "access_index"]]
X_scaled = StandardScaler().fit_transform(X)
tree = linkage(X_scaled, method="ward")
df["cluster"] = fcluster(tree, t=3, criterion="maxclust")
print(df.groupby("cluster")[["service_index", "access_index"]].mean())
print(df["cluster"].value_counts().sort_index())

How to read it: the code selects the relevant columns, applies the algorithm, and prints a summary or evaluation. Results can vary with random sampling and package versions. For a real project, document the split, parameters, metrics, and any preprocessing choices.

13 / QUALITY CHECK

Common mistakes to avoid

  • Leaving the linkage method undocumented.
  • Comparing distances before considering feature scales.
  • Treating a dendrogram cut as an objective truth.

Before publishing a conclusion, ask whether the data supports the statement, whether the chart matches the stated method, and whether a reader could reproduce the workflow from the included files.
